# SPEC

扩展在 PI TUI 底部状态栏展示当前模型流式输出的两个指标:token 速率(TPS)与首 token 延迟(TTFT)。状态行形如:

```plaintext
TPS 62 tok/s · TTFT 1.2s
```

两个指标相互独立:各自采样、各自冻结,不互相推导。任何指标都只在流式过程中产生读数。

## 通用规则

1. 只处理 assistant 消息的流式事件;其它角色的消息不参与统计。
2. 指标标签 `TPS` 与 `TTFT` 恒为 `dim`,不上色;只有数字按色带上色。
3. 流式过程中数字按色带展示;响应结束后数字变为 `dim`,并保留最后一次读数。
4. 响应中止或出错时不更新读数,继续显示上一次读数;若从未测到过则显示占位符。
5. 不保存会话历史:session 启动时清空所有读数,状态行暂时清空。
6. 无 UI(JSON / print 模式)时不采样、不绘制。

## TPS(token 速率)

1. 只统计流式过程中的速率,不做整段平均、不做结算。
2. 速率来自尾部滑动窗口;provider 上报的 `usage.output` 与字符估算各用一条窗口,互不相减。
3. 流式中数字的色带:
   - 显示值大于 50 tok/s:绿色
   - 显示值 10 ~ 50 tok/s:黄色
   - 显示值小于 10 tok/s:红色

   颜色按实际显示的数字分桶,保证数字与颜色一致。

4. 非流式(响应结束后)数字为 `dim`,保留最后一次读数。
5. 无数据时显示 `TPS — tok/s`。

## TTFT(首 token 延迟)

1. 度量口径:从该次模型请求发出(assistant 消息的 `timestamp`)到首个 token 事件到达的间隔。它包含网络、排队与 prefill,不包含本地 prompt 组装。
2. 每次 assistant 响应各自计算并覆盖上一条读数;工具调用链中每发起一次模型请求就刷新一次。
3. 首个 token 指最早出现的以下事件:`text_start`、`thinking_start`、`toolcall_start`,或非空的 `text_delta`、`thinking_delta`、`toolcall_delta`。
4. 单位自适应:先把毫秒四舍五入,`round(ms) < 1000` 用整数毫秒(如 `840ms`),否则用一位小数秒(如 `1.2s`)。这样 `999.6ms` 显示为 `1.0s`,不会出现 `1000ms`。
5. 流式中数字的色带:
   - 显示值小于 1s:绿色
   - 显示值 1s ~ 3s:黄色
   - 显示值大于 3s:红色

6. 非流式(响应结束后)数字为 `dim`,保留最后一次读数。
7. 无数据时显示 `TTFT — ms`。

## 状态行

1. 段之间用 `dim` 的 `·` 分隔,TPS 在前、TTFT 在后。
2. 状态行 key 为 `token-rate`,由 `/token-rate` 命令统一开关。

## 性能

1. 写入节流 150ms;每次 delta 都必须喂给指标,节流只影响绘制。
2. 不使用定时器;指标不持有任何 timer / handle。
